# team-review 手順書

Claude Codeを「進行役」、GPT・Geminiを「論者」として、1つのお題を3ラウンドの議論にかけ、最終的に
進行役が統合判断する手順です。KANAEの核になっている仕組みそのものです。

**Claude Codeで使う場合**、このファイルの内容をそのまま会話で渡し、「この手順で、お題は〇〇について
実行して」のように指示してください。`.claude/commands/`配下にスラッシュコマンドとして置くこともできま
すが、環境によって認識されたりされなかったりするため(Claude公式デスクトップアプリ内蔵版では認識され
ないことを確認済み)、会話内で直接指示する方法を基本の使い方として案内しています。

## ステップ-1: スリープ防止(開始時に必ず実行、Windows限定・任意)

議論中にPCがスリープしてAPI通信が中断されないよう、開始前に以下を実行してスリープを無効化する。
Windows以外の環境、またはスリープの心配がない環境では省略してよい。

```powershell
powershell -File scripts/sleep-guard.ps1 -Action start
```

## 最終ステップ: スリープ設定の復元(終了時・中断時に必ず実行)

議論(役割分担会議〜統合レポート保存)がすべて終わったら、上記でスリープ防止を実行した場合は必ず
以下を実行して元のスリープ設定に戻す。途中でエラーになり議論を中断する場合も、放置せず必ずこれを
実行すること。

```powershell
powershell -File scripts/sleep-guard.ps1 -Action stop
```

GPT・Geminiへの質問は、それぞれ以下のコマンドで実行する(カレントディレクトリはリポジトリ直下)。

```bash
node scripts/ask-gpt.js "質問文"
node scripts/ask-gemini.js "質問文"
```

## ステップ0: 役割分担会議

1. 上記お題を、GPT・Geminiの両方に提示し、次のように尋ねる:
   「これから次のお題について、AIチームで議論します。あなたはこの案件で
   『リサーチ担当』と『プロデューサー担当』、どちらが向いていると思いますか?
   理由も一言添えてください。お題: {お題}」
2. 両者の回答を踏まえて、以下の固定パターンA/Bのどちらかを選ぶ(自由に新しい役割分担を作らない):
   - パターンA: GPT=リサーチ担当、Gemini=プロデューサー担当
   - パターンB: GPT=プロデューサー担当、Gemini=リサーチ担当
   - 両者の希望が一致すればそれに従う。**割れた場合(希望が重複した場合を含む)や判断が難しい場合は、
     進行役があなたお題の内容から適切な方を選ぶ。**
     (余談:GPT・Geminiが両方とも「プロデューサー担当」を希望して重複するケースが、実際に何度も起きて
     いる。珍しいことではないので、その場合も慌てず進行役が機械的に裁定すればよい。)
3. 決定した役割分担を、ユーザーへの報告用に一言でまとめておく。

## ステップ1〜3: 3ラウンドの議論ループ

決定した役割(リサーチ担当/プロデューサー担当)を各質問の冒頭に明記した上で、
以下の3ラウンドを順番に実行する。ラウンド2・3では、相手の直前の回答をプロンプトに含めること。

1. **ラウンド1(率直な意見)**: 「あなたは{役割}です。次のお題について、率直な意見を聞かせてください。お題: {お題}」
2. **ラウンド2(弱点の指摘)**: 「あなたは{役割}です。相手(もう一方のAI)は次のように答えました:『{相手のラウンド1回答}』。この意見の弱点・見落としていそうな点を指摘してください。」
3. **ラウンド3(統合案)**: 「あなたは{役割}です。ここまでの議論(自分の意見・相手からの指摘)を踏まえて、最終的にどちらの意見が良いか、または両方を統合した案を提案してください。」

## ステップ4: 統合レポート

3ラウンドすべての発言(GPT・Gemini双方、計6回分)を俯瞰し、進行役(Claude)として統合判断を行い、
以下の構成でレポートをまとめる。

1. お題
2. 役割分担とその理由(ステップ0の結果)
3. 各ラウンドのやり取り(要約でよい。全文ログは別途保存する)
4. 最終的な統合判断・結論
5. (該当する場合)実演・紹介用に使えそうなポイントのメモ

レポートは `{テーマスラッグ}_team-review.md` として保存する。
また、全ラウンドの生ログ(質問・回答の全文)も、`{テーマスラッグ}_team-review-log.md` として別途保存
する(実際に何が出力されたかを、あとから改変なしで確認できるようにするため)。

保存が終わったら、レポートの要点をユーザーに報告する。

実際にこの手順を動かした例は、[../examples/demo-review/](../examples/demo-review/)を参照。
